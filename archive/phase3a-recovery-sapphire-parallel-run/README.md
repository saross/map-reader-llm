# Sapphire-side parallel run — Phase 3a recovery (archived)

> **Last revised**: 2026-05-12 (original publication — archived after sapphire-state reconciliation). See [§ Changelog](#changelog) for revision history.

## What this is

A complete snapshot of the **sapphire-side overnight execution** of the Phase 3a verifier-completeness recovery campaign, preserved per the project's *Preserve and compare, don't discard* policy after sapphire's working-tree state was superseded by an independent zbook-side re-run.

## Why it exists

The Phase 3a verifier-completeness recovery campaign was launched on sapphire as an overnight job on 2026-05-03. The resume driver started at 15:19 UTC and reported `Recovery driver complete. Cumulative cost: $0.904930` at 15:28 UTC — a successful run covering 10 of 11 Tier-2/3 cells (plus 1 Tier-1 catch-up cell), recovering 530 missing candidates across 11 cells.

Sapphire then went off-network during user travel from 2026-05-04. Recovery work continued on zbook locally; Sessions 86–87 (2026-05-05/06) closed the entire 14-cell campaign on zbook ($1.89 cumulative spend) and committed the results to `origin/main`. When sapphire came back online on 2026-05-12, its working tree still held the 22 modified files (post-cleanup probabilities + run-meta for the 11 cells) plus 22 pre-cleanup backups — all artefacts of the May 3 overnight that never reached origin.

Rather than `git checkout` away that state, this archive preserves it for the parallel-run comparison documented in `results/sapphire-zbook-cleanup-comparison.md`.

## How to use

The archive is browseable in the working tree per project policy. To inspect:

- Per-cell probabilities: navigate to `post-cleanup/outputs/<cell-path>/probabilities.json`. Each contains a `cleanup_history` entry recording the sapphire-side recovery (timestamp 2026-05-03, recovered=N, still_missing=0).
- Per-cell pre-cleanup state: matching `pre-cleanup/outputs/<cell-path>/probabilities.json.pre-cleanup-<timestamp>.backup`.
- Resume run narrative: `logs/phase3a-recovery-overnight-resume/stdout.log` — operator-readable trace of each cell's cleanup attempt.

For the formal comparison against `origin/main`, see `results/sapphire-zbook-cleanup-comparison.md`. Comparison script at `scripts/compare_sapphire_zbook_cleanup.py`.

## Authoritative state

This archive is **historical** — `origin/main` carries the authoritative post-cleanup state, generated by the independent zbook re-run. The sapphire-side data should not be used as the input to downstream analyses; use `outputs/<cell-path>/probabilities.json` (zbook origin/main) for any current or future work. The archive's purpose is reproducibility documentation, not analysis input.
