### PROJECT OVERVIEW

**Map Reader LLM** is a production-ready automated pipeline for extracting burial mounds ("Tumuli") from Soviet-era topographic maps using Google Gemini's multimodal Large Language Models. The project is designed to support the Tundzha Regional Archaeology Project and represents advanced prompt engineering applied to remote sensing and archaeology.

**Key Metadata:**
- Authors: Shawn Ross, Adela Sobotkova
- License: Apache 2.0 (code), CC-BY 4.0 (docs)
- Status: Active development with recent methodology archiving (as of Dec 22, 2025)
- Funding: Australian Research Council (ARC) Linkage scheme

---

### SYSTEM ARCHITECTURE & PIPELINE

The project implements a modular, reproducible detection pipeline with three primary strategies:

#### **1. Data Flow**
```
Raw GeoTIFF Maps → Tiling (1024x512px chunks with geospatial metadata)
    ↓
Inference Engine (Stage 1) → Candidate Detection
    ↓
Verification Engine (Stage 2) → Confidence Scoring
    ↓
Analysis & Reporting → Performance Metrics
```

#### **2. Core Components**

**Preprocessing (preprocess_tiling.py)**
- Slices large GeoTIFF maps into manageable tiles with World Files (`.pgw`)
- Preserves geospatial metadata (EPSG:32635 UTM Zone 35N)
- Generates `.aux.xml` sidecar files for georeferencing
- Input: `/inputs/rasters/*.tif`
- Output: `/inputs/tiles/{map_name}/*.png`

**Stage 1: Inference Engine (4_detect_mounds_batch.py)**
- Main orchestration script (v4.1.0)
- Constructs multimodal prompts: system text + reference images + target tiles
- Queries Google Gemini API with versioned configurations
- Implements parallel processing with ThreadPoolExecutor
- Error handling: 429 rate limits, 503 server errors, MAX_TOKENS retries
- Output: `outputs/results/vX.X/candidates.geojson` + `.meta.json`
- Tracks comprehensive metadata (prompt hash, git commit, token usage, timing)

**Stage 2: Verification Engine (5_verify_crops.py)**
- "Reviewer" in proposer-reviewer workflow
- Extracts high-resolution crops around candidates
- Performs visual chain-of-thought analysis: Scan → Discriminate → Score
- Filters out hard negatives with confidence scoring (0.0-1.0)
- Supports consensus voting across multiple iterations
- Output: `outputs/results/vX.X/verified.geojson`

**Analysis & Metrics (7_analyze_consensus.py, 6_accuracy_report.py)**
- Calculates Precision, Recall, F1 against ground truth
- Performs grid-search simulation for voting thresholds
- Supports spatial tolerance metrics at 10m, 20m, 30m, 50m buffers
- Bootstrap confidence intervals via resampling

### DOCUMENTED CHALLENGES & LEARNINGS

#### **Lessons from 14+ Observations:**

1. **"Going with the Grain"**: Models exhibit strong natural associations (e.g., Gemini links elevation numbers with mounds). Rather than suppressing, exploit these correlations.

2. **Visual Blindspots**:
   - Bisected symbols (grid lines crossing centers) break gestalt
   - Clustered/overlapping symbols confuse Non-Maximum Suppression
   - Solution: Explicitly instruct reconstruction of broken symbols

3. **False Positive Challenges**:
   - Bridge decoys (black dots on roads confused with benchmark symbols)
   - Pareidolia on numbers (2,3,6,8,9,0 resemble circles)
   - Unrolled mounds (embankment hachures misidentified as mounds)

4. **Text vs Image Modality**:
   - Flash *requires* text scaffolding at high temps; Pro doesn't
   - Text constraints introduce "modality interference" (models second-guess visual patterns)
   - Solution: **Image-only few-shot prompts are superior**

5. **Consensus > Verification**:
   - Stochastic agreement (voting 2/5) is more reliable than logical deduction (two-stage verifier)
   - Verifier pipeline (v4.6) failed despite initial promise (F1 0.72 vs 0.91)

6. **The "White Void" Hallucination**:
   - Edge tiles with >90% white padding cause token runaway (MAX_TOKENS errors)
   - Solution: Information density check before tile selection

7. **The "Anti-Number Paradox"**:
   - Explicitly listing negative examples (digits) paradoxically increases false positives
   - Better to rely on positive definition & lighter touch on negatives

8. **Balanced Few-Shot Strategy**:
   - 3 positive + 3 negative examples more effective than single positive
   - Explicitly teaches model what "nothing" looks like (Sparse areas, Topography, Urban clutter)
