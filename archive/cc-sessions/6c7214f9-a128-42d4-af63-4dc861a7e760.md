## V4.x Two-Stage Implementation Review - Findings

I've completed a thorough code review. **I found multiple implementation issues that explain the poor v4.x performance.**

### Critical Bug #1: Missing Instruction File

The `v4.6_verifier.json` config references:
```json
"instruction_file": "v4.6_verifier_instructions.md"
```

**This file does not exist.** The available instruction files are:
- v3.0, v3.1, v3.2, v3.5, v3.6, v3.7 — but no v4.6

When the file is missing, `5_verify_crops.py` falls back to a hardcoded 12-line default prompt (lines 126-141). This basic fallback lacks the sophisticated reasoning structure your visual CoT approach requires.

### Critical Bug #2: Contradictory Example Labels

In `v4.6_verifier.json` lines 13-24:
```json
{"label": "Negative Example: Hard Benchmark", "path": "benchmark_mound.png"},
{"label": "Negative Example: Hard Triangulation", "path": "triangulation_mound.png"}
```

**These are POSITIVE examples!** `benchmark_mound.png` and `triangulation_mound.png` show mounds WITH benchmarks/triangulation markers on them—they're valid detections.

By labelling them negative, you're explicitly training the verifier to **reject valid mound detections**. This directly explains the catastrophic recall (0.57) with near-perfect precision (0.97)—the verifier learned to reject anything that looked like a benchmark or triangulation on a mound.

### Issue #3: Unused Config Flags

The config has `"visual_cot": true` and `"confidence_rubric": true`, but `5_verify_crops.py` doesn't actually use these flags to modify behaviour. They're decorative.

### Issue #4: Temperature 0.0

The verifier uses deterministic temperature (0.0), leaving no room for uncertainty on edge cases. Given the visual ambiguity in these maps, some temperature headroom might help.

**The v4.x failure is NOT a fundamental flaw in two-stage architecture—it's implementation bugs.**

| Strategy | Claimed Benefit | Actual Evidence | Gemini 3 Result |

The 17% accuracy drop in the cited research was for **counterfactual images** where VLMs have strong priors:
- Adidas logos (model "knows" they have 3 stripes)
- Dogs (model "knows" they have 4 legs)

For burial mound symbols on Soviet maps, there's **no conflicting prior knowledge**. The task is pure visual pattern matching against novel domain content. Text-image interference requires priors to interfere with.

**This explains why v3.2 (detailed text rules) outperforms v3.5/v4.x (stripped text)**: The text rules HELP because there's nothing for them to conflict with.

1. **Compounding errors** - Two chances to fail, not two chances to succeed
2. **Context loss** - Verifier loses full map context when seeing cropped regions
3. **Threshold interaction** - Proposer's liberal + verifier's strict thresholds interact unpredictably
4. **Systematic failures** - Two-stage introduces systematic errors that voting can't fix
