### Caveat: T=0.0 results are not transferable to Phase 3a

The T=0.0 consensus result (F1=0.6566) exploits run-to-run variation
that existed in the **canonical library** used for Phase 2b (4 unique
patterns across 10 runs). Phase 2c/2d/2e demonstrated that the current
**plus-hp library** produces near-perfect determinism at T=0.0 (only 2
unique patterns: F1=0.6201 for 7/10 runs, F1=0.5823 for 3/10 runs,
mean=0.6088). With truly deterministic runs, consensus voting has no
filtering effect — the output at any threshold equals any single run.

The T=0.0 row should therefore be interpreted as a demonstration that
consensus works when variation exists, not as a viable Phase 3a
configuration.

### Comparison to plus-hp single-run baseline

The plus-hp library at T=0.0 achieves mean F1=0.6088, which is already
higher than all Phase 2b single-run means (canonical library, best
T=0.0 mean=0.5573). The best Phase 2b consensus result excluding T=0.0
(T0.3 N=10 x=8, F1=0.6421) exceeds the plus-hp single-run mean by
+0.033 — suggesting that consensus voting on plus-hp data at T=0.3
could push performance beyond the current single-run ceiling.

## Methodology

This analysis reuses Phase 2b temperature sweep data (5 temperatures x 10 runs) with zero additional Application Programming Interface (API) calls. For each (temperature, pool_size, threshold) combination:

1. Detection GeoDataFrames are converted to GeoJSON features
2. Within-run deduplication (20 m tolerance) removes overlapping-tile duplicates
3. Cross-run clustering (20 m tolerance) groups detections and counts votes
4. Vote threshold filters clusters by minimum agreement
5. Consensus centroids are spatially joined to tile boundaries for F1 evaluation
6. Bootstrapped 95% CIs use tile-level resampling (K=1000 iterations)

Pool selection: N=5 uses runs 1-5 (preregistration Section 3.8 first-five convention); N=10 uses all runs.
