# The 3.7 flex tier was unavailable on 2026-09-16, and what that cost

> **Last revised**: 2026-09-16 (original publication — the drift probe's
> failure, its diagnosis, and the decision it forced). See
> [§ Changelog](#changelog) for revision history.

## What was being attempted

A model-drift probe before spending ~US$446 completing the image
proposer × verifier 2×2 to K = 5. Runs 4–5 of the existing Gemini 3.7 image
pool must come from the same sampler as runs 1–3, or the K ladder measures
model drift confounded with K. The Gemini application programming interface
(API) exposes no dated build for these models — across 1,241 registered passes
every `model_version` it has ever returned equals the requested alias, and
`gemini-3-flash` returns none at all — so an empirical probe is the only
instrument available.

The probe: re-run 500 of run_1's own tiles today, compare per-tile detection
counts against runs 1–3 restricted to those same tiles. Baseline agreement
among the three committed passes is **0.8878 ± 0.0032**, total counts within
**0.36 %** — tight enough to detect a changed sampler.

## What happened

The probe dispatched 212 requests over roughly ten minutes and **completed
none**. `avg_lat` never left `N/A`; `429s` stayed at 0.

The campaign's own run_1 log settles what normal looks like on this exact
script, config, tier and machine:

| | first completion | at ~50 s | avg latency |
|---|---|---|---|
| Campaign run_1 (2026-09-13) | **20 s** | 97 done / 198 requests | 22–31 s |
| Probe (2026-09-16) | **none at 600 s** | 0 done / 202 requests | **N/A** |

## The diagnosis

One direct call, four combinations, error text unswallowed:

| model | tier | result |
|---|---|---|
| `gemini-3.7-flash` | **flex** | **503 UNAVAILABLE after 77.9 s** — "This model is currently experiencing high demand" |
| `gemini-3.7-flash` | standard | OK in 1.4 s |
| `gemini-3-flash-preview` | flex | OK in 11.0 s |
| `gemini-3-flash-preview` | standard | OK in 1.1 s |

**The model is fine; Google's flex capacity for it was not.** The batch driver
retries 503s with 30 s exponential backoff (`--base-wait` default), which
produces exactly the observed signature: dispatch count climbing, zero
completions, no latency sample, and `429s = 0` because these are 503s rather
than rate limits.

## Why the signature was hard to read

Three properties of the failure conspired:

1. **A 503 is indistinguishable from slowness at the progress bar.** The bar
   reports completions; retries are invisible to it.
2. **`requests=` counts attempts, not tiles.** A climbing counter looks like
   progress and is equally consistent with a retry storm.
3. **The driver swallows the error text.** The diagnosis needed a call made
   outside the retry wrapper.

The reliable tell was not in the probe at all — it was the **campaign's own log
as a baseline**. Twenty seconds to first completion against ten minutes of
nothing is unambiguous where "slow" is not.

## Decisions taken

- **The 3.7 uplift is HELD.** It cannot run on flex, and the standard tier is
  2× the price (US$163.75 → US$327.50) — a cost-mode escalation that is the
  Principal Investigator's (PI) call, not an agent's.
- **The drift question is UNANSWERED**, not answered negatively. Nothing is
  known about whether runs 4–5 would match runs 1–3.
- **The Gemini 3 leg PROCEEDED.** The probe only ever gated the 3.7 uplift,
  which appends to an existing pool; the Gemini 3 pool is new, so there is no
  prior pass for it to be consistent with and drift is meaningless for it. It
  runs on flex normally — 4.69 it/s, avg latency 20.3 s, ETA ~85 min per pass.

## Operational notes

- Failed 503s are not billed, so the stalled probe's cost is the dispatch
  attempts only.
- A cheap tripwire for any future flex run: make one call before launching the
  batch and assert it returns. Seventy-eight seconds of waiting would have
  replaced ten minutes of ambiguity.
- The pass driver judges liveness by **log staleness**, not `pgrep`, per
  `docs/agent-guidance.md`, and its fallback pattern is bracketed so it cannot
  match its own command line.
