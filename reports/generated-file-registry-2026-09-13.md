# Generated-file registry rebuild, and the drift guards it asked for

> **Last revised**: 2026-09-13 (original publication). See
> [§ Changelog](#changelog) for revision history.

**Verdict**: the registry now enumerates 3,619 documents across `results/`,
`reports/`, `outputs/` and the `docs/methodology` mine subset, attributes
every one of them, and records for each generated document whether it meets
the 2026-09-11 generated-projections ruling's three obligations. Queried
against it, the count of generated documents in **neither** compliance
regime — six on this morning's audit — is now **0**. Ten documents were
regenerated to get there, and not one number in them moved.

**Items**: 11a and 11b of
`planning/documentation-foundation-checklist-2026-09-13.md`.
**Commits**: `86ba12413` (11a), `acd4ed054`, `b16954d4c`, `80e897049` (11b),
and this report's own commit.
**Instrument**: `scripts/build_generated_file_registry.py` →
`reports/verification/generated-file-registry.json`, map
`reports/verification/apparatus/generator-map.json` v1.1.

## 1. Why the registry had to be rebuilt first

`planning/interim-docs-review.md` § 11.5 item 3 called the registry "the
instrument that would classify these", and found it stale: built
`2026-08-20T08:24:18` at `git_head` `06f7b8ea5`, holding 2,131 files, short
of the tree by 814 `results/**.md` and 48 `reports/**.md` — and by charter
blind to `outputs/` entirely. So the audit's headline finding, "six generated
documents in neither compliance regime", was the product of a reading pass
over a graded inventory rather than a query over the project's own
classifier. Item 11a's job was to make that sentence checkable.

## 3. What the registry now records per generated document

The ruling gives a generated projection three obligations. The registry
records each as evidence rather than opinion, so the audit question is a
query (`--gaps`) instead of a reading pass:

| Field | Evidence |
|---|---|
| `generated_banner` | a do-not-hand-edit banner in the document's first 15 lines. Deliberately narrower than the registry's older marker test: a bare `**Generated**:` timestamp is a claim about *when* a file was written, which is why all 46 cell evaluations have one and none is compliant |
| `source_commit_stamp` | a git hash in the head, named as the commit the inputs were read at. Requires the hash, so prose about commit messages does not count |
| `check_mode`, `check_flags` | the `check`-family CLI modes **parsed out of the generator's argparse** — options starting `--check`, or a `check-…` subcommand verb in a positional's `choices` |
| `check_tests`, `tier1_check_test` | test modules that name the generator *and* use one of its own check modes, with the tier-1 verdict |
| `regime2_compliant` | the conjunction of the four |

The parse matters. An earlier draft grepped for quoted `check-…` strings and
credited **2,396** cell evaluations with a drift guard they do not have,
because `scripts/evaluate_detections.py` runs `git check-ignore`. A test
pins that case (`test_discover_check_modes_reads_argparse_not_prose`).

The registry is itself a generated artefact, and now carries its own guard:
`_meta.git_head` is the stamp, `--check` the drift mode (which also
neutralises `generated_at`), and
`tests/test_build_generated_file_registry.py` runs that check against the
committed file — ~2 s for the whole corpus, the same bargain
`tests/test_generate_run_reports.py` strikes for the 41 committed run
reports. A second test asserts no marker-carrying file is unattributed.

## 4. The guards added (item 11b)

Ten documents, four generators, all now compliant. Each was regenerated
once; **content drift was zero in every case** — the diff is the banner and
the stamp.

| Documents | Generator | Guard added | Tier-1 test | Tests |
|---:|---|---|---|---:|
| 5 register renderings: `results/{runs,conditions,passes,analyses}-manifest.md`, `results/run-registry.md` | `scripts/generate_post_run_report.py` | source-commit stamp + `--check-renderings` (+ `--render-manifests`) | `tests/test_manifest_renderings.py` | 6 |
| `…/gs-era2-verified-board-2026-09-10/tiering_20m.md` | `scripts/era1_leaderboard_tiering.py` | banner, both commits, `--check <board dir>` (+ `--render-md`) | `tests/test_era2_board_renderings.py` | 8 |
| `…/gs-era2-verified-board-2026-09-10/frame-deltas.md` | `scripts/build_gs_era2_board.py` | banner + stamp, `check-renderings` (+ `renderings`) | same module | — |
| 3 55-map boards: `55map-leaderboard-50m{,-standardised,-r2}.md` | `scripts/build_55map_leaderboard.py` | banner + stamp, `--check` | `tests/test_55map_leaderboard_renderings.py` | 7 |
| the registry itself | `scripts/build_generated_file_registry.py` | `--gaps`; tier-1 test on the existing `--check` | `tests/test_build_generated_file_registry.py` | 20 |

Design points worth recording:

- **Every guard renders from committed JSON.** Not one of them re-runs a
  permutation test, re-scores a cell or reads anything under `outputs/`.
  That is what makes them tier-1 affordable and, more importantly, what
  makes them safe: a drift guard that recomputes could *change* the thing it
  is checking.
- **The tiering banner carries two commits.** The commit the board was
  computed at (from `tiering_20m.json`'s own `git_commit`, `30a27f361`) is
  the provenance that matters and is **not** neutralised — a board
  recomputed at another commit is a different board. The render commit is
  neutralised, so re-rendering is not drift.
- **`renderings` is separate from `gates`** in the board script because
  `gates` rewrites `gates.json` with a fresh `checked_at_utc`. Adding a
  banner must not move a gate report.
- **The refactor is its own evidence.** `era1_leaderboard_tiering.py`'s
  Markdown writer previously took the in-memory `ordered` and `tier_of`; it
  now reads `result["ranking"]`. That the committed 150-cell table
  re-renders byte-identically proves it was a pure projection of the JSON,
  which the audit could only assume.

## 5. A correction to the audit's framing

`planning/interim-docs-review.md` § 11.4 counted "the four
`results/55map-leaderboard/*.md` tables" as one generated class in neither
regime. Three are generated boards. The fourth,
`gs-vs-55map-transfer.md`, has **no generator and no sidecar JSON** — the
generator map already filed it hand-written under rule
`hw-gs-55map-transfer` — so it owes regime 1, and it now carries a
Last-revised banner and a Changelog with a 2026-06-11 original-publication
stub. The four tables split across both regimes rather than sitting in one,
and a tier-1 test asserts the distinction cannot quietly invert (the
hand-written one must carry `Last revised` and must **not** carry a
do-not-hand-edit banner).

## 6. What did NOT change

- **No register content.** No row of `results/runs-manifest.json`,
  `conditions-manifest.json`, `passes-manifest.json`,
  `analyses-manifest.json` or `run-registry.json` was touched; the JSONs
  were read, never written. `run-registry.json` remains the hand-authored
  input whose Markdown alone is generated.
- **No board cell, rank, tier, tie set, withheld-cell row or signature
  field.** The Era-2 board's 150-cell F1 tiering, its MCC family, its
  three withheld cells and its 110-cell frame-delta table are byte-identical
  apart from the added banner line. A test asserts the withheld-cell
  disclosure survives a re-render.
- **No 55-map board number.** The committed r1 board JSONs are G3/G4
  regression-gate targets; `--rebuild-md` is a render-only path and the
  rewrite guard was left in place for the compute path.
- **No figure in `gs-vs-55map-transfer.md`** — every GS F1@50, MCC, k3, k4
  and Δ is as published on 2026-06-11.
- **`docs/paper/results-draft.md` and
  `docs/paper/results-claims-inventory-2026-09-12.md`** were not touched:
  item 9 was running in parallel.
- **The 2026-09-11 ruling itself.** This work applies it; it does not amend
  it.

## 7. What remains, named

1. **The 46 `outputs/**/evaluation.md` files** — the ruling's one open
   class. All 46 carry a `**Generated**:` timestamp, none carries the
   ruling's banner, and `scripts/evaluate_detections.py` has no check mode.
   Closing it is a generator change on the project's most-used script, which
   is why it is a decision and not a chore; it is registered in the
   compliance table as the open class.
2. **17 further `tiering_20m.md`-family documents** written by
   `scripts/era1_leaderboard_tiering.py` for earlier analyses. The generator
   now carries the guard, so each is one `--render-md <board dir>` away from
   compliance; they are left for back-fill-on-touch, because re-rendering
   another analysis's board is that analysis's business.
3. **3,268 of 3,318 generated documents carry no banner.** This is the
   tree's shape, not a backlog: the ruling reaches paper-facing projections,
   and the standing rule for the rest is back-fill on touch. `--gaps`
   prints the live list grouped by generator, worst first, so the next pass
   can pick by leverage: 2,396 cell evaluations, 393 experiment intents, 115
   PV sweep summaries, 113 AB+ notes.
4. **Five documents carry a source-commit stamp but no banner**
   (`results/55maps-fp-classification/report.md`,
   `results/gs-fp-classification/report.md`,
   `results/metric-leaderboards/55map-canonical-50m.md`,
   `results/metric-leaderboards/gs-era2-pv-family-30m.md`,
   `results/student-gt-fn-rate-analysis/report.md`). Half-way to regime 2

## 9. Reproduction

```bash
# The registry: rebuild, drift-check, and the regime-2 gap list
python3 scripts/build_generated_file_registry.py --strict
python3 scripts/build_generated_file_registry.py --check
python3 scripts/build_generated_file_registry.py --gaps

# The four drift guards (each reads committed JSON; nothing is recomputed)
.venv/bin/python scripts/generate_post_run_report.py --check-renderings
.venv/bin/python scripts/era1_leaderboard_tiering.py --check \
    results/leaderboard/era2/gs-era2-verified-board-2026-09-10
.venv/bin/python scripts/build_gs_era2_board.py check-renderings
.venv/bin/python scripts/build_55map_leaderboard.py --check

# The tier-1 tests that run them
.venv/bin/python -m pytest -m tier1 -q \
    tests/test_build_generated_file_registry.py \
    tests/test_manifest_renderings.py \
    tests/test_era2_board_renderings.py \
    tests/test_55map_leaderboard_renderings.py
```
