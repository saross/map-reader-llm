# Combined / cross-architecture tier leaderboards

**Generated**: 2026-04-26 (Session 80, combined cross-architecture build)
**Scope**: per-Era all-vs-all rankings — every condition in an Era competes
in a single greedy-clique BH-FDR-tiered table, regardless of architecture.

## What this directory contains

For each Era × buffer × metric × q-level combination, a tier table that
includes **every condition in that Era pooled across all four
architectures** (single-pass, consensus, single-pass + Provider–Verifier
(PV), PV-only). All C(N, 2) within-Era pairwise comparisons are
BH-FDR-corrected together within one (Era × buffer × metric × q-level)
family.

This complements — and does not replace — the within-architecture
stratified tier tables at `../per-architecture/`, which constrain pairwise
tests to within-architecture pairs and therefore answer a different
question (best-in-class within each architecture rather than best-overall
in the Era).

## Methodology

Identical to the per-architecture tier construction, with the only change
being the condition pool that enters BH-FDR (now Era-wide rather than
stratum-wide):

- **Inventory**: `planning/condition-inventory-with-s78.json`. Per Era,
  conditions are pooled across all populated `(architecture, status)`
  combinations as currently used by `scripts/run_per_arch_leaderboards.sh`
  (`READY` for consensus and PV; `SINGLE_PASS_ONLY` for single-pass;
  `PV_READY` for single-pass + PV).
- **Bounds**: Era 1 → 340-tile 512 px; Era 2 → 487-tile 384 px (Era 2
  scope per `feedback_384px_scope_preference`); Era 3 → 327-tile 384 px
  (pool_160 excluded).
- **Per-cell threshold selection**: F1-maximising at 20 m primary buffer
  (Option A semantics — fixed across all per-buffer F1 re-tiering).
- **Pairwise permutation tests**: 10,000 iterations, seed 42, paired
  tile-swap (F1) or per-tile (TP, TN, FP, FN) classification swap (MCC).
- **Per-buffer F1**: 5 separate runs per Era × q-level, one per buffer,
  each writing to its own `pairwise_f1_<B>m/` cache.
- **MCC**: a single run per Era × q-level (the tile-level MCC permutation
  test is buffer-independent).
- **BH-FDR family scope**: all C(N, 2) pairs within one (Era × buffer ×
  metric × q-level) combination, q ∈ {0.05, 0.01}.
- **Greedy-clique tiering**: conditions sorted by metric descending; each
  appended to the current tier if BH-adjusted p ≥ q against every
  current member, otherwise a new tier starts.

## Cache reuse

The within-architecture pairwise caches generated by the
per-architecture build (commits `b4c28d5b` + `d6969a74` + the per-buffer
F1 follow-ups) are hardlinked into the combined cache dir before this
build runs, so within-architecture pairs are read from disk and only the
cross-architecture pairs are computed fresh. See
`scripts/build_combined_leaderboard.sh`.
