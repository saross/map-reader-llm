## Durable mitigation — patch `evaluate_detections.py`

The root cause of the audit trigger (today's discovery of missing
metadata in `outputs/55maps-image-generalisation/evaluation/evaluation.json`)
is that `scripts/evaluate_detections.py` writes CI fields but not
bootstrap parameters. A one-line mitigation will prevent the same
gap recurring for future `evaluation.json` outputs.

- **File**: `scripts/evaluate_detections.py`
- **Proposed change**: in `evaluate_single_condition()` (line ~137),
  where the returned dict is built, include the top-level keys
  `"_metadata": {"n_bootstrap": n_bootstrap, "seed": seed,
  "resampling_unit": "tile", "generating_script": __file__,
  "script_version": __version__, "git_commit": <resolved sha>}`.
  Likewise for the batch writers at lines ~499 and ~536.
- **Estimated developer time**: ~15 minutes plus a smoke test.
- **Impact on existing files**: none. Past `evaluation.json` files
  remain `INFERABLE`; future ones become `YES`.
- **Recommended companion patch**: add the same metadata block to
  `scripts/build_tiered_leaderboard.py`'s
  `leaderboard_all_evaluations.json` writer (closes the P2 gap above).

## Why no re-runs

In the original task brief, the expected output was a prioritised
re-run list. The registry audit found that all CI-bearing files in
this repository resolve to retrievable metadata via one of three
paths: (a) in-file metadata blocks, (b) co-located run manifests, or
(c) version-controlled script defaults. The only residual friction is
that (c) requires a reader of the paper to consult the generating
script as well as the output file. The durable mitigation above
collapses (c) into (a) for future runs without re-running any past
experiment.

## If the mitigation is adopted

Applying the proposed `evaluate_detections.py` patch will affect
future outputs only. If you subsequently regenerate any
`evaluation.json` (for example, as a by-product of re-running a
pipeline with a new ground-truth file), the new output will
automatically record the full metadata block. There is no need to
re-run past experiments purely to capture metadata — the script
defaults at the file's timestamp are sufficient for paper citation.
