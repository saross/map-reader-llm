# Review App Screenshots — Paper Figure Candidates

Screenshots from `scripts/review_candidates.py` (the calibrated-tolerance
Streamlit app introduced 2026-04-20) captured during the human review of
1,028 VLM-only candidates on the 55-map image generalisation run.

Purpose: illustrative figures for the paper's methodology and discussion
sections. Candidate categories:

- **Clear detections**: unambiguous mound symbols fully inside the 50 m
  tolerance circle.
- **Fuzzy / distorted symbols**: degraded map symbols that the pipeline
  still correctly identified.
- **Superposition / multi-period features**: e.g. benchmark-on-mound on
  top of a tell (see `docs/notes/reflections/working-notes.md` Obs 262).
- **True false positives**: clear non-mound features correctly rejected
  as FP.
- **Ambiguous cases**: symbols at the tolerance-circle boundary,
  illustrating the ~10–15% noise band discussed in Obs 263.

## Naming convention

`review-example-<short-descriptor>-candidate_<id>-<YYYY-MM-DD>.png`

Short descriptor should summarise what the figure illustrates, hyphenated.
Example descriptors:

- `fuzzy-distorted-symbol-detected`
- `clear-mound-inside-circle`
- `symbol-centre-outside-circle`
- `benchmark-on-tell-superposition`
- `clear-non-mound-rejected`
- `ambiguous-boundary-case`

## How to add a new screenshot

1. Take the screenshot in your OS's native screenshot tool (lands in
   `~/Pictures/Screenshots/` by default on Ubuntu).
2. Copy into this directory with a descriptive filename per the
   convention above.
3. Add a row to the capture log with candidate id, category, and a
   one-line note about what the figure illustrates.

Avoid redundant captures: one example per illustrative point is enough
for the paper. If you have multiple screenshots of the same kind, pick
the clearest.
