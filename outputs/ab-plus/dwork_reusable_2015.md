## Summary (Claude's synthesis — advisory, unverified)

Dwork and colleagues (Science, 7 August 2015; authors listed alphabetically) diagnose a failure mode this study is structurally exposed to, and offer an algorithmic rather than procedural remedy. Their premise is that inference theory around false-discovery-rate control “assumes that a fixed procedure is performed, selected before the data are gathered”, whereas real analysis is adaptive, with new analyses chosen from data exploration and from earlier analyses of the same data — an implicit multiple-comparisons problem that reported significance levels and existing false-discovery-rate techniques do not capture. They name two prior responses. Preregistration — “defining the entire data analysis protocol ahead of time, thus forcing the analysis to be nonadaptive” — is safe but, they judge, burdensome and slow to gain momentum. Validating on a holdout is safe until an outcome from it conditions the next choice: the statistic so selected is no longer independent of the holdout, and “the only known safe approach is to collect new data for a fresh holdout set”, which they call very costly and frequently abused.

Their own contribution makes one holdout reusable: the analyst reaches it only through a differentially private mechanism, bounding what can be learned about any single record, and so the scope for overfitting; the formal guarantees sit in supplementary material absent from the extracted text. Thresholdout is the instantiation — if a statistic’s training and holdout values differ by less than a noisy threshold, return the training value, otherwise the holdout value plus Laplace noise. The demonstration is synthetic and Freedman-inspired: with n = 10,000, d = 10,000 and labels drawn uniformly at random, so that 50% is the ceiling on true accuracy, naive reuse reported >63 ± 0.4% at k = 500 selected variables — on training and holdout sets alike — while Thresholdout prevents the overfitting and returns a valid estimate.

The intersections are direct: this study reuses one small gold standard across phases to choose thresholds, aggregation variants, and operating points, then carries that calibration to a 55-map deployment; each choice is one turn of the adaptive loop, and the carried-versus-oracle transfer taxes are its empirical measure of the resulting optimism. The sharpest point for us is that the inflation appears on the holdout too, so a reference set never refreshed cannot detect its contamination — the deployment-scale comparison is the nearest thing to fresh data, its annotation budget the price Dwork et al. say analysts frequently decline to pay. Two cautions travel with any import. Neither cross-validation nor bootstrap resolves the issue for their experiment’s structure, which bounds what bootstrap intervals can be claimed to control. And Thresholdout is neither free nor metric-agnostic: its guarantee as stated covers statistics expressible as the mean of a bounded function f : X→[0,1], which F1 and MCC are not; and at T = 0.04 the reported accuracy is off by up to 0.04 whenever training and holdout agree within that band, so any analogous tolerance would have to be smaller than the differences one intends to claim.

### KP1
- **Quote (verbatim):** "the holdout set, in general, is not reusable. If the analyst uses the outcome of the validation to select an additional data statistic, that statistic is no longer independent of the holdout data, and further use of the holdout set for validation can lead to incorrect statistical inference."

- **Paraphrase:** Once a validation result is used to choose what to test next, the chosen statistic is no longer independent of the holdout, so further validation on that same holdout no longer licenses standard statistical inference. The failure is created by selection conditioned on a previous outcome, not by the number of times the holdout is touched — one conditioned reuse is enough.

### KP4
- **Quote (verbatim):** "In this scenario no classifier can achieve true accuracy better than 50%. Nevertheless, reusing a standard holdout results in reported accuracy of >63 ± 0.4% for k = 500 on both the training set and the holdout set."
- **Locator:** page_index 2 · p.3 · Main text — first synthetic experiment (uncorrelated label)
- **Paraphrase:** In a synthetic design engineered to contain no signal at all — n = 10,000 (a labelled set of size 2n split at random into equal training and holdout halves), with d = 10,000 attributes drawn from N(0,1), class labels drawn uniformly at random, so 50% is the ceiling on true accuracy — reusing a standard holdout produced a reported accuracy above 63% (± 0.4 being the standard deviation over 100 independent executions) when 500 variables were selected, and the inflated figure appeared on the holdout set as well as the training set. The magnitude is specific to this constructed no-signal setting and is not a general estimate of holdout optimism.

### KP5
- **Quote (verbatim):** "We first note that neither cross-validation nor bootstrap resolve this issue. If we used either of these methods to validate the correlations, overfitting would still arise as a result of using the same data for training and validation (of the final classifier)."
- **Locator:** page_index 2 · p.3 · Main text — why standard resampling does not help here
- **Paraphrase:** For the two-step select-then-classify procedure in their experiment, neither cross-validation nor the bootstrap removes the overfitting, because the same data would still be doing both jobs. The claim is scoped to that structure — it is not a general verdict that resampling never helps, and it concerns selection-induced optimism rather than sampling variance, which is what a bootstrap interval does estimate.

### KP6
- **Quote (verbatim):** "adapting the analysis to data results in an implicit multiple comparisons problem that is not captured in the reported significance levels of standard statistical procedures or by existing techniques for controlling the false discovery rate"
- **Locator:** page_index 0 · p.1 · Main text — introduction, the adaptivity problem
- **Paraphrase:** Choosing an analysis after looking at the data amounts to an unreported multiple-comparisons problem: the significance levels standard procedures report, and the false-discovery-rate corrections built for a fixed family of tests, do not account for the comparisons implicitly made during exploration.

### KP7
- **Quote (verbatim):** "Thresholdout was invoked with T = 0.04 and t = 0.01, which explains why the accuracy of the classifier reported by Thresholdout is off by up to 0.04 whenever the accuracy on the holdout set is within 0.04 of the accuracy on the training set."
- **Locator:** page_index 2 · p.3 · Main text — Thresholdout parameter settings in experiment 1
- **Paraphrase:** The protection is bought with deliberate imprecision: with the threshold set at T = 0.04, any validated statistic — in the paper’s setting, the mean of a bounded function f : X→[0,1] — whose holdout value sits within 0.04 of its training value is reported as the training value, so the returned number can be wrong by up to 0.04. (The extracted text renders the paper’s tolerance parameter τ as a plain “t”; T and τ = 0.01 are different parameters.) Adopting a reusable holdout therefore costs reporting resolution, and the band has to be smaller than the differences one intends to claim.
